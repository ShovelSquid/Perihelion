# Phase quick-261001-14s Plan 01: Optional hitboxes with collider registry Summary

Hitbox is now optional: each Object collects its Hitbox-layer limb colliders and Hitbox-component colliders into a static AimPart registry, and HandRig's aim assist scans that registry and passes an owner-layer weight into ScorePart.

## What changed

- `Assets/Scripts/Hitbox.cs`: Hitbox keeps its damage path but drops its own registry. New `AimPart` class (collider, optional hitbox, owner) with `Active`, `Register`, `Unregister`, `IsRegistered(Collider)` and a SubsystemRegistration reset.
- `Assets/Objects/Object.cs`: `hitboxLayerName = "Hitbox"` under `[Header("Aim Assist")]`; `CollectAimParts()` at the end of Awake (non-trigger colliders on the layer, plus Hitbox-component colliders on any layer, excluding anything under an Item or a nested Object); `protected virtual OnEnable/OnDisable` register and unregister. Missing layer logs one warning per session and falls back to Hitbox components only.
- `Assets/Scripts/HandRig.cs`: `slot.target` and `GetTarget` are `AimPart`; `EvaluatePart(AimPart ...)`; `ownerLayerWeights` (List<LayerWeight>) plus `defaultLayerWeight = 1f`; `OwnerLayerWeight(owner)` reads `owner.gameObject.layer`; `ScorePart(Collider col, Hitbox hitbox, float ownerLayerWeight, float angleOffCentre, float coneAngle, float distance)` is the single TODO(human), stub returns angleOffCentre.
- `ProjectSettings/TagManager.asset`: user layer 15 = `Hitbox` (one-line diff, CRLF kept).

## Deviations from Plan

**1. [Rule 1 - Bug] LayerWeight is a class instead of a struct**
- **Found during:** Task 1 (orchestrator amendment asked for `weight = 1f`)
- **Issue:** Assembly-CSharp.csproj uses LangVersion 9.0; struct field initializers are C# 10+, so a struct with `= 1f` would not compile.
- **Fix:** `[System.Serializable] public class LayerWeight`; OwnerLayerWeight skips null entries.
- **Commit:** ac76ab9

**2. [Orchestrator amendment] Owner body colliders don't block line of sight to its parts**
- `HasLineOfSight(origin, point, partCollider, partOwner)` ignores a hit when it belongs to the part's owner (`GetComponentInParent<Object>() == owner`) and is not a registered AimPart. That check only runs for hits that would become the nearest. The owner's other registered parts still block (arm hides head). AimPart keeps a `Dictionary<Collider, AimPart>` for the registered check.
- **Commit:** ac76ab9

**3. [Rule 3 - Blocking] TagManager edit tool**
- Git Bash `sed -i` stripped the file's CRs and failed to match. Restored that one file with `git checkout -- ProjectSettings/TagManager.asset` and did a byte-exact CRLF-preserving edit with node. Final diff is the single intended line.

## Notes for the user

- Untick the Hitbox layer against the layers it shouldn't touch in Physics > Layer Collision Matrix. If the editor was open during the TagManager edit, check that Tags and Layers shows User Layer 15 = Hitbox (type it in if not).
- Bullets still hit an enclosing movement capsule first (Projectile.hitMask ~0), so damage goes to the Object, not the part. Aim line of sight now ignores the owner's own capsule, but bullets don't. Put movement capsules on a layer excluded from Projectile.hitMask, or shrink them so the limbs stick out.
- Limb colliders under a Rigidbody still count toward its automatic center of mass and inertia tensor even with collisions off in the matrix. If a character's balance shifts, set those on the Rigidbody by hand.
- A Hitbox with no Object above it is no longer aimable (bullets still damage it).
- `GetTarget` now returns `AimPart`.
- LayerWeight is a class with `weight = 1f`; depending on how the inspector creates the first list element, a new entry may still show 0 or 1. Check the value when you add one.
- ScorePart's new parameters (hitbox may be null, ownerLayerWeight) are waiting for your weighting.
