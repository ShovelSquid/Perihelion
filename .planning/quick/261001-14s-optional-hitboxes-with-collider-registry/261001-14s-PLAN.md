Choices made at Claude's discretion (the SPEC doesn't fix these):
- The registry is a plain class `AimPart` in Hitbox.cs. Its entries are reference types, so `part == current` and List.Remove work by identity. Hitbox stops self-registering, and its registry and reset move to AimPart. Consequence: a Hitbox with no Object above it is no longer aimable, though bullets still damage it.
- The layer weights live on HandRig and are shared by both hands, as `List<LayerWeight>` where LayerWeight is `{ LayerMask layers; float weight; }`. The first entry whose mask holds the owner's layer wins. A LayerMask gives an inspector dropdown instead of typed layer names.
- `GetTarget` now returns `AimPart` (collider + optional Hitbox + owner). Nothing outside HandRig calls it.
- Inactive child colliders are collected too (includeInactive), and EvaluatePart skips them while inactive, so parts switched on later still work.
- A Hitbox entry's owner is the Hitbox's explicit `owner` when set, else the collecting Object. That matches the owner BulletManager charges.
- An empty `hitboxLayerName` means Hitbox-component-only collection, with no warning.
