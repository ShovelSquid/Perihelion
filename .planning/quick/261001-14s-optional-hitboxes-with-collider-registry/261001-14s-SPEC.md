# Spec: optional hitboxes + owner-layer aim priority (agreed with user, 2026-10-01)

Follow-up to quick task 260930-x5h (Hitbox.cs, HandRig ideal/real aim points).

## Decisions (LOCKED)
- Hitbox component becomes OPTIONAL. Aim assist searches plain colliders too.
- Body-part colliders live on a dedicated "Hitbox" physics layer (user unticks it in the Layer Collision Matrix so limbs don't collide with the world / the character's own Rigidbody). Do NOT add kinematic rigidbodies or IgnoreCollision.
- `Object` collects its aimable colliders once in Awake: every non-trigger child collider on the Hitbox layer, plus any child collider that has a Hitbox component (any layer). Exclude colliders under a held Item. Registered into a static registry of aimable parts (collider + optional Hitbox + owner Object); unregister on disable/destroy/death like Hitbox does today. Reset registry on SubsystemRegistration (domain reload off). Layer resolved by name via a public string/serialized field (default "Hitbox"); if the layer doesn't exist, log one warning and fall back to Hitbox-component-only collection.
- Aim priority uses the OWNER's layer (`owner.gameObject.layer`), not the collider's layer. Each hand / HandRig gets a tunable list of layer -> weight entries (e.g. Enemy 2, Destructible 1); unlisted layers use a default weight (1). Pass it into scoring.
- `HandRig.EvaluatePart` / `UpdateIdealPoint` work on the registry entries (collider + optional Hitbox). `slot.target` must still let Gun/AimCursor/GetTarget callers work: keep the public accessor shape compatible or update all call sites.
- `ScorePart` signature becomes `(Collider col, Hitbox hitbox /*may be null*/, float ownerLayerWeight, float angleOffCentre, float coneAngle, float distance)`. It REMAINS the single TODO(human) with a compiling stub (return angleOffCentre). Do not implement its real logic. Doc comment must say hitbox may be null and aimWeight defaults to 1.
- `assistMask` stays; its default should include the Hitbox layer so limbs block line of sight (DefaultRaycastLayers already includes custom layers — verify, don't over-engineer).
- Bullets: unchanged behaviour — Hitbox on struck collider first, else GetComponentInParent<Object>(). Projectile.hitMask default ~0 already hits the Hitbox layer.
- The project must define the "Hitbox" layer in ProjectSettings/TagManager.asset if a free user layer slot exists (check the file; add only the layer name, change nothing else). If no free slot, skip and note it for the user.
