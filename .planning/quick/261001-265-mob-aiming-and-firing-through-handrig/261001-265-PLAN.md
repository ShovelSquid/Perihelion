Choices made at Claude's discretion (the SPEC doesn't fix these):
- The aim point is placed on the aim centre on every Update with a live target, not only while engaged. Range and sight are measured to that centre anyway, and HandRig's eased aim depth is then already settled on the frame engagement starts. This is a superset of "each Update while engaged".
- shootRange is measured in 3D from the eye to the aim centre. keepDistance is measured flat from the body to target.position, the same way stopDistance already is. When not engaged, the existing stopDistance still applies.
- A target with no Object above it counts as alive, and its aim centre is always the aimHeight fallback.
- Changing `target` to a different transform while engaged disengages first, so the new target gets a fresh reactionTime and no trigger stays held across the switch.
- Facing runs in a new FixedUpdate (a physics step, where MoveRotation belongs), yaw only, using Quaternion.RotateTowards toward a flat LookRotation.
- On death, OnDisable calls HandRig.SetAiming(false) directly instead of Mob.Aim(false). Die has already deactivated the GameObject, so Mob.Aim(false) would log a coroutine error and do nothing.
- The helper starts at eye.position + eye.forward * keepDistance, so HandRig's first eased depth isn't measured to the world origin.
- Only items with usesAiming get trigger presses. A mob never pulls the trigger on a non-aiming item it happens to hold, such as food.
- The sight buffer holds 32 hits, so the mob's own limbs and held items can't crowd out a real blocker.
- Every hand presses as soon as reactionTime ends. The per-burst cooldown jitter desyncs the hands after that.
