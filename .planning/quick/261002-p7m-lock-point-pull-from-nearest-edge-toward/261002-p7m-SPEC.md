# Spec: lock point pull from nearest edge toward part centre (agreed with user, 2026-10-02)

Follow-up to quick task 261002-k3a (eye-space assist cone).

## Problem
A locked hand's ideal point is the part's point nearest the eye ray (`ClosestPoint` twice in `EvaluatePart`). Near a part, that is its edge, so the cursor frame moves only the small gap from the crosshair to the outline and shots graze the silhouette.

## Decisions (LOCKED) — user picked option C
- New `Item.lockPull` ([Range(0, 1)], default 0.65) in the Aim header: 0 = nearest edge (old behaviour), 1 = the part's centre.
- Centre = `col.ClosestPoint(col.bounds.center)`, so it stays on or in the collider.
- The ideal point = `Lerp(edgePoint, centre, lockPull)`.
- Candidacy and scoring are unchanged: the cone test and `angleOffCentre` use the edge point, so pull never changes which part wins.
- Line of sight is checked to the pulled point. If that is blocked, fall back to the edge point if it is visible; otherwise reject the part. The extra raycast only runs when the pulled point is blocked.
- `ScorePart` distance uses the final point. `ScorePart` stays the `TODO(human)` stub.

## Conventions
As in 261002-k3a. Verify by Unity recompile in the open editor (Editor.log) and by grepping `EvaluatePart` call sites.
