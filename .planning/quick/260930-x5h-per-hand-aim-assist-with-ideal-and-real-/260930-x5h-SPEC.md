# Spec: per-hand aim assist (agreed with user, 2026-09-30)

## Hitboxes (skinned characters -> regular colliders on bones)
- New `Hitbox` component on each body-part collider. Maps collider -> part data (name, own health pool, armor, aimWeight e.g. head > 1) -> owning `Object` (GetComponentInParent). Damage to a part reduces the part pool AND feeds back to the owning Object.
- `BulletManager.OnBulletHit` resolves `Hitbox` first, falls back to `Object` as today.

## Aim layers
1. Centre aim target: `AimInput` camera ray (unchanged). The chooser's reference is a smoothed "general look" direction, not the exact crosshair hit, so flicking across a gap does not drop the target.
2. Per-hand IDEAL aim point (state on `HandRig.HandSlot`; only active when the slot's item uses aiming; any item type, tuning comes from the item):
   - Candidates: Hitbox colliders inside that hand's cone. Cone = HandRig shot cone origin + bloom (degrees). No conecast in Unity: broad phase (OverlapSphere/static Hitbox registry), per-part `collider.ClosestPoint` to the aim ray, angle off centre, line-of-sight raycast from cone origin.
   - Scoring by weights = exactly ONE `TODO(human)` function for the user (e.g. angleOffCentre / aimWeight). Stub must compile and return a sensible default.
   - Sticky: a new candidate must beat the current one's score by 20% (tunable).
   - No candidate -> falls back to the centre aim target. Hands may pick different parts.
   - Bloom circle centre is projected from the ideal point.
3. Per-hand REAL aim point: what the gun/muzzle actually aims at and what the dot is drawn from.
   - Sways around the ideal point inside a tunable radius.
   - Recoil kicks push it off the ideal point; an underdamped spring pulls it back (overshoot allowed; reuse offsetFrequency/offsetDampingRatio semantics).
   - Lerps toward the ideal at a tunable speed so it travels across depth when the target changes.
   - Sway radius and kicks authored in DEGREES, converted to metres at the target distance.
   - Tightness: item tuning `onTargetAccuracy` (shrinks the sway sphere while locked on a part) and `offTargetLooseness` (considerably loosens it when not on a target); blended by whether the hand has a target.
- Dot: `WorldToScreenPoint` of the real point, depth ignored; clamp/handle z < 0 (behind camera).
- REPLACE the existing angular muzzle `offset`/`restPoint` sway+kick path in HandRig with this real-point model; do not layer a second noise source. Shot direction (Gun cone shot) must stay consistent: shots go from muzzle toward the real point, with per-shot scatter inside bloom as today.
