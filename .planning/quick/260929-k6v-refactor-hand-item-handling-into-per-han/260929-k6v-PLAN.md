<objective>
Refactor the player's hand/item handling into a per-hand slot system owned by a new `HandRig` component: two slots (Right, Left), each with an externally supplied socket (pre-IK animated hand pose), its TwoBoneIK target, and the equipped Item. HandRig is the sole writer of IK targets, derives each item's rest pose from its placing socket, and hands that pose (or the item's aimTarget while aiming) to `AimItem`, which becomes a pure physics driver. Mob stops owning IK targets and a single held item and just asks HandRig to "equip item X into hand Y". `IKHandAttach` is deleted.

Purpose: one item per hand (dual wield) and two-handed items, with the hand pose coming from animation instead of a fixed hold transform, and a socket source that a future ghost/pose armature can replace without touching HandRig.
Output: `Assets/Scripts/HandRig.cs` (new), reworked `AimItem.cs`, `Item.cs`, `Mob.cs`, `PlayerManager.cs`, `Hotwheel.cs`; `IKHandAttach.cs` + `.meta` removed; SUMMARY with the manual in-editor rewiring steps.

Coverage of the agreed intent (no REQ IDs / CONTEXT / RESEARCH for quick tasks; source is the planning_context bullets):
- HandRig with two slots (socket, ikTarget, Item), sole IK writer: Task 1 (A)
- One item per hand, two-handed uses both, dominant places + off-hand IKs, EquipInfo flags + primaryHand: Task 1 (A, C)
- Socket-derived pose formula, grips = handL/handR: Task 1 (A)
- Socket source-agnostic (constraint today, ghost armature later): Task 1 (A); rig setup in SUMMARY manual steps
- Aim at aimTarget while aiming, socket pose replaces the hold target: Task 1 (A, B, C)
- AimItem pure physics, IK fields/copy block removed, interpolation on: Task 1 (B)
- Delete IKHandAttach + .meta: Task 2 (B)
- Mob requests equip via HandRig, IK/hand-slot concerns out of Mob, no wider Mob cleanup: Task 1 (D)
- Callers updated so the project compiles (Hotwheel, HotwheelSlot, PlayerManager, Player, Gun, Item): Task 1 (E), Task 2 (A). HotwheelSlot, Player and Gun were checked and reference none of the removed members, so they are not modified.
- No YAML edits; manual steps in SUMMARY; keep user comments; explicit staging only: both tasks + output section
</objective>

<assumption_delta_decision>
Signal: pluralization. One held item per Mob becomes one item per hand slot.
Primary noun: the hand slot (`HandRig.HandSlot`, addressed by `HandSide`).
Decision: promote. HandRig's slots become the only record of what is held. `Mob.item` is removed, not kept next to the slots. Readers that need "what is held" ask HandRig (`GetItem`, `IsEmpty`, `ForEachItem`). Keeping `Mob.item` would let the two drift apart, e.g. a left-hand item that the single field can't represent.
Invariant test (optional, offered, not added): "for every held item, the slots it occupies match its EquipInfo flags, and exactly one of them places it". There is no Unity test assembly in the project yet, so this is left to the user.

  2. If GetSlot(side).item is this item and that slot places it, return true. The item is already held there, which makes Hotwheel's re-equip of the current item a no-op.
