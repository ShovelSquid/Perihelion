<objective>
Rework HandRig's aim in three ways. First, each hand gates on whole objects before scanning their hitbox parts. Second, each hand's look leads or trails the crosshair depending on which way the view turns, and the hands converge on the crosshair when it settles. Third, dual-wielded hands always share the centre part. AimOff also gets the same framerate-independent exponential lerp as everything else.

Purpose: the user said, verbatim, "every hand should scan all possible object/overall colliders, and if its in one that has hitbox parts it should then only scan those aimparts, aimoff should use the same lerp as everything else, and we should set shouldconverge to true. I just want to have the right arm moving right faster when looking right and having the left arm trail a little bit slower, and vice versa when looking left but they should converge at the same center position".

Output: AimBody in `Assets/Scripts/Hitbox.cs`, body collection and registration in `Assets/Objects/Object.cs`, the object-first scan, lead/trail and convergence in `Assets/Scripts/HandRig.cs`, and the exponential lerp in `Assets/Scripts/AimOff.cs`.

Locked decisions (user and orchestrator; implement exactly):
- D-01 Object-then-part scan. A new `AimBody` class goes in Hitbox.cs next to AimPart, one per Object. It has `owner`, `bodies` (non-trigger, non-part colliders wrapped as `AimPart(col, null, owner)`) and `parts` (the existing hitbox parts). It also has a static `Active` list, Register/Unregister, and a SubsystemRegistration reset that mirrors AimPart. Body wrappers must never go into AimPart's collider-lookup dictionary, so `AimPart.Register` stays hitbox-parts-only. Object.CollectAimParts also collects the body colliders, using the same Item and nested-Object skip rules. It builds one AimBody when there are any bodies or parts, and OnEnable/OnDisable register and unregister it alongside the parts. In HandRig, EvaluatePart's pure geometry is split into a helper. Each AimBody is gated with a cheap encapsulated-bounds sphere cull, then passes if the cone touches any of its colliders, bodies first and then parts. If it passes, only its `parts` are scored when it has parts, otherwise its `bodies`. All of this goes in one `FindBest(...)` helper used by both UpdateSharedTarget and UpdateIdealPoint, with a skip parameter for the current lock. AimBodies whose owner is self or destroyed are skipped. The sticky current-lock re-score stays as it is.
- D-02 AimOff: the Lerp helper becomes an exponential ease, `1f - Mathf.Exp(-aimSharpness * deltaTime)`, with a new `public float aimSharpness = 10f; // per second` field.
- D-03 ShouldConverge returns true, with a short comment, and its TODO(human) is removed. The ScorePart TODO(human) is left untouched.
- D-04 Lead/trail per hand replaces the static split. Remove the split-angle field and its direction helper. Add `[Header]`-grouped `leadSharpness = 25f` and `trailSharpness = 8f` (per second). UpdateAimTarget stores the exact eye-to-aimPoint unit direction in `aimDir`. HandSlot gets NonSerialized `lookDir` and `hasLookDir`, reset in ResetAimState. Each frame, each hand works as follows. With no lookDir yet, it snaps to aimDir. Otherwise: delta = aimDir - lookDir; turn = dot(delta.normalized, lookSource.right) * (Right ? 1 : -1), which is 0 when the delta is tiny; sharpness = Lerp(trail, lead, 0.5 + 0.5*turn); lookDir = Slerp(lookDir, aimDir, 1 - exp(-sharpness*dt)). The hand's cone axis is its lookDir, and its no-lock fallback is eye + lookDir * aimDistance. The shared-target path keeps the centre axis (lookReference). This applies to every placing hand. Comments that mention the split are updated.

Claude's discretion (choices made while planning, already dry-run in a scratch copy):
- `AimPart.IsLive(Collider)` is the single copy of the "exists, enabled, active in hierarchy" test. It is shared by EvaluatePart, the gate and `AimBody.TryGetBounds`.
- The geometry helpers are `ColliderInCone`, `SphereInCone`, `AnyInCone`, `BodyGate` and `ClosestOn`. `ClosestOn` falls back to `bounds.ClosestPoint` for collider types Collider.ClosestPoint doesn't support (non-convex mesh, terrain and similar). Body colliders are often exactly those, and an unsupported ClosestPoint would put the "nearest point" on the aim axis itself, so every such body would gate in.
- The gate's range test is measured to the encapsulated sphere's near side (`centreDist - radius > assistRange`), so a big object whose centre is out of range doesn't hide parts that are in range. The per-collider test keeps today's centre-distance rule.
- Without a look source or an aim distance, UpdateAimTarget computes no direction. StepHandLook then returns false and the hand uses the centre axis and `aimTarget` exactly as before. That makes the design's "side 0 with no lookSource" case moot.
- `CollectAimParts` keeps its name. The old list field is replaced by `aimBody`, which is the one source of truth. The `aimPartsRegistered` flag keeps its name.
